# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

    make                 # build/mellagui (compositor), build/mellagui-term, build/mellagui-calc, build/mellagui-run, build/mellagui-settings, build/mellagui-view, build/mellagui-record, build/mellagui-calendar
    make run             # build + start mellagui on a real VT (EXEC=, TIMEOUT=, HEADLESS=1)
    make asan            # build/mellagui-asan (ASan + UBSan)
    make fuzz-run        # coverage-guided fuzzer of the whole compositor, FUZZ_TIME=60 s (tests/fuzz_server.c, see docs/FUZZING.md)
    build/keymap-test    # layout tables / keymap generator unit test (also run by tests/run.sh)
    tests/run.sh         # all end-to-end tests (needs a built build/mellagui; plus mellagui-term etc. for TestClients)
    MELLAGUI_BIN=build/mellagui-asan tests/run.sh      # same under the sanitizers (exit code 77 / "Sanitizer" in output = failure)
    python3 -I tests/test_mellagui.py TestWindows.test_move_with_titlebar     # a single test
    build/mellagui --backend headless --size 1024x600 --socket t0 --control /tmp/ctl      # manual headless run
    python3 tools/ppm2png.py frame.ppm frame.png                  # to look at a `dump` from the control socket

Only gcc, make, pkg-config and the libdrm headers exist on the dev machine (no libwayland, xkbcommon, libinput,
wlroots, meson ...); nothing may depend on them. No X11 anywhere. Tests need `XDG_RUNTIME_DIR` (the harness sets one).

## Architecture

Single-process, single-threaded epoll loop (`src/loop.c`); a from-scratch Wayland server (no libwayland).
`docs/ARCHITECTURE.md` and the header comments in `src/*.h` are the module contracts; read the header before a `.c`.

Data flow:
* **input**: `input_evdev.c` (or `lm_input_inject` from the headless control socket) → `seat.c`
  (`lm_seat_handle_input`) → `wm.c` first (`lm_wm_key` shortcuts, `lm_wm_pick`/`pointer_button` for frames and panel) →
  only if the wm declines, `wl_keyboard`/`wl_pointer` events to the focused client.
* **output**: client `wl_surface.commit` → `surface.c` copies the shm buffer into the surface's own texture and calls the
  role's `damage` hook → `xdg.c` forwards to `lm_wm_surface_damage` → `render.c` accumulates per-output damage →
  `backend_*.c` `get_framebuffer`/`present` → `output_ready` (page-flip event or 60 Hz timer) → frame callbacks.
* **windows**: `xdg.c` is only a protocol adapter; all policy (placement, focus, maximize, move/resize grabs, workspaces,
  decorations geometry, panel layout with the round logo button that opens the About dialog, the dock, shortcuts) lives in `wm.c`, which also exposes the scene (`lm_wm_scene_for_each`)
  that `render.c` paints bottom-to-top. The wm talks back to clients only through `struct lm_window_ops`.
* **request dispatch** (`server.c`): object table per client, handlers get already-validated/resolved args; protocol
  violations → `wl_display.error` + disconnect. Interface signature tables are hand-written in `protocol.c`
  (opcodes are named in `protocol.h`); `wire.c` is shared with the clients.
* **user configuration**: `~/.config/mellagui/mellagui.conf` (`--config FILE|none`, headless: none; `--print-config` prints the built-in one) is an INI file read by `conf.c` (sections, `key = value`; each section belongs to one module, `conf_line` in main.c only dispatches). So far `[commands]` (terminal, run, settings, view) -> `launchers.c` (which also expands command lines for the dock and `[keys]` `exec`: `@terminal`-style tokens, `a || b` alternatives, `~/`, bare `mellagui-*` found next to the binary); the old `[menu]` section (the MellaGUI app menu is gone, the dock replaced it) is ignored without a warning. * **window animations**: `[windows] animation-ms` (default 300, 0 = off; the headless backend never animates unless `MELLAGUI_ANIMATIONS` is set: a number above 1 is the time in ms, 1 the metrics value, 0 off - tests use 1500). A window that opens (`anim_open` at the end of `lm_wm_window_map`), is minimized (`anim_fly` in `lm_wm_window_request_minimize`), comes back (`lm_wm_focus_window`) or closes is shown as a **ghost**: `lm_render_snapshot` (render.c) paints its FRAME and SURFACE over black and over white into a premultiplied `struct lm_ghost` (wm.h; the black/white trick of `gl_scratch_alpha`), the wm moves, scales and fades it (`struct wm_anim`, `anim_state`: open = grows from 90 % and fades in, close = shrinks to 92 % and fades out, minimize / restore = flies between the window and its dock icon or taskbar button (`anim_target`), 16 ms timer) and the scene emits it as `LM_SCENE_GHOST` above the windows, below the panel (`paint_ghost` bilinear in software, `lm_gl_draw_tex` with alpha in `render_gl.inc`). While an opening / restoring ghost runs the real window is left out of the scene (`lm_window.anim_hidden`). A close only animates when the window was asked to close first (`lm_wm_window_close` keeps its picture in `close_ghost` for 3 s, `anim_play_close` in `lm_wm_window_unmap`); a client that just exits disappears at once. **Dragging**: with animations on, a window dragged by its title bar does not jump to the pointer but glides after it (`anim_glide_to` from `grab_motion`: the target goes in `glide_tx/ty`, `anim_tick` moves the window by `1 - exp(-dt / tau)` of the remaining distance, tau = animation-ms / 5, at least 20 ms) and keeps gliding to the end point after the button is let go; a new grab or the window going away stops it (`grab_begin`, `anim_forget`). **Wobble** (`[windows] wobble`, 0..100, default 60, 0 = rigid; needs animations on, so the glide above is the fallback): a window dragged by its title bar is painted as a mesh (`struct wm_wobble`, `WB_COLS` x `WB_ROWS` = 14 x 32 cells cut from a picture of the window, emitted as `LM_SCENE_GHOST` items with `src` = the cell and `dst` = the bounding box of its four nodes; `paint_ghost` and `render_gl.inc` take the `src` part) whose nodes are damped springs (`wobble_step`: stiffness 1600 near the grab point, `1600 * 0.07^strength` far from it, plus a pull towards the neighbours' mean so the bend travels as a wave). The real window moves with the pointer at once and is hidden (`anim_hidden`) meanwhile; the picture is taken again every 6th tick (~100 ms) so the content stays alive; after the button is let go the mesh settles and ends (`wobble_tick`). Started by the first motion of a title-bar grab (`grab_motion`), stopped by a new grab, the window going away or a workspace switch. Control socket `anim` shows `wobble=0|1`. Not animated: fullscreen windows, the calendar, dmabuf (zero copy) windows, windows over 8 M pixels, workspace switches (they end running animations). Control socket `anim`. Tests `TestAnimation`. The GL path (`render_gl.inc`) passes the same tests with `MELLAGUI_RENDERER=gl` (headless GL); it was not looked at on a real DRM screen.

Input: `overview_pick` (`LM_PICK_OVERVIEW_ITEM` / `_WS` / `LM_PICK_OVERVIEW`, below the panel and the dock, which keep working) and a modal key block in `lm_wm_key` (arrows / Tab choose, Enter / Space goes to the window, Delete closes it, 1..4 switch workspace, Esc / Super+W close); a click is done on release on the same thing (`overview_click`): a picture = `overview_close(idx)` (focuses it, a minimized window comes back without its own fly-in: `anim_suppress`, then the pictures fly back), middle click = close the window, right click = the window menu (Move to workspace ...), **a press that moves 8 px carries the picture** (`overview_drag_motion`: it shrinks to 55 % and follows the pointer, its place in the grid stays as a faint copy; dropped on a workspace cell the window moves there with `move_to_workspace` and the pictures are taken again, dropped anywhere else nothing happens and it is no click: `overview_drag_finish`), a workspace cell = `lm_wm_switch_workspace`, the empty space = close. `overview_changed` (called from map / unmap / move_to_workspace / workspace switch / output change) takes the pictures again, so the overview follows windows that come and go. * **H.264 (own encoder and decoder)**: `src/h264.[ch]` (bit writer / reader, the CAVLC code tables of ITU-T H.264 9-5 .. 9-10, integer transforms, quantizer scales, DC intra prediction), `src/h264enc.[ch]`, `src/h264dec.[ch]`. Gotchas:
* wm coordinates: `lm_window.{x,y,width,height}` is the *window geometry* (client area); the frame is drawn around it
  (see `wm.h`). Workspaces are 0-based in the control socket output.
* Sub-surface position and `set_window_geometry` take effect on the *parent's* commit (protocol-correct; tests rely on it).
* The headless backend's `windows`/`dump`/`sync` commands are the test oracle; add a test in `tests/test_mellagui.py`
  (helpers: `Window`, `Ctl`, `Ppm` in `tests/wlclient.py`) when changing behaviour.
* The XKB keymap text is generated (`lm_keymap_build`) and cannot be compiled here (no libxkbcommon): real xkbcommon clients (VS Code) are the only way to verify it.
* Devices: with a usable logind session (`--logind auto`, default) `src/logind.c` (a from-scratch D-Bus client, `docs/ARCHITECTURE.md`) hands out the DRM and evdev fds and does VT switching (`PauseDevice` → ack, `ResumeDevice`, `Seat.SwitchTo`); otherwise plain `open(2)` + VT_PROCESS, which needs groups `video`+`input`. Backends call `lm_dev_open` / `lm_dev_close` so both paths share the code. Tested only against `tests/fake_logind.py` (`TestLogind`, `build/logind-test`) and by hand up to `TakeControl` on the real logind.
